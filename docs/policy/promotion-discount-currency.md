# 프로모션 할인과 통화

- Status: **제안(proposal)**. 승인되지 않았습니다.
- 승인자: 미정 (제품 + finance-ops)
- 승인일: —
- Rollout: **§6의 production inventory 확인 전에는 미승인**입니다. 이 문서만으로
  Admin 차단을 배포하지 않습니다.

관련 파일을 바꾸기 전에 읽어 주세요.

- `lib/billingPromotionCore.ts`
- `lib/billingPromotionSecurity.ts`

- `app/api/billing/promotion/validate/route.ts`

## 1. 이 문서가 생긴 이유

AUD 시장에서 Pro 월간 A$20.00에 USD 고정액 코드 `PAYMENTTEST27`($14 off)을
적용하면 주문 요약이 `-$14`와 **A$1.33 due today**를 표시하고, "결제 계속하기"가
영어 오류로 거절했습니다. A$1.33은 환율이 아니라 비율입니다 — $15에서 $14를 뺀
비율 93.3%를 호주 가격 A$20.00에 곱한 값이고, **그런 AUD 할인은 DB에도 Stripe에도
없습니다.**

계약 불일치 자체는 수정됐습니다(#624). validation이 Checkout과 같은 통화 판정을
하고, 요약은 청구 가능한 것만 그립니다. 이 문서는 그 수정이 **드러낸** 질문에
답합니다: 고정액 할인을 여러 통화로 확장할 것인가.

## 2. 결정

**신규 프로모션은 정률 할인만 허용합니다.**

고정액 할인(`discountAmountCents`)의 다중 통화 지원은 도입하지 않습니다. 기존
USD 전용 코드는 만료까지 grandfathering하고, 컬럼은 삭제하지 않습니다.

## 3. 왜 정률인가

1. **시장별 요금이 환산값이 아닙니다.** 카탈로그는 시장마다 따로 정한 값입니다.

   | | USD | AUD | EUR | KRW | CNY |
   |---|---|---|---|---|---|
   | Pro 월간 | $15.00 | A$23.00 | €14.00 | ₩20,000 | ¥108.00 |

   $15에 어떤 환율을 곱해도 이 네 숫자가 나오지 않습니다. 가격이 결정이므로
   **할인액도 결정**이지 계산 결과가 아닙니다.

2. **정률은 가격이 바뀌거나 통화가 추가돼도 의미가 유지됩니다.** 50% 할인은
   새 시장이 생겨도 그대로 50% 할인입니다. 고정액은 캠페인마다 5개 통화 값을
   finance가 승인하고 계속 관리해야 합니다.

3. **비용이 provisioning 하나가 아닙니다.** Stripe coupon `currency_options`,
   Admin UI, reconciliation, webhook 금액 검증, 캠페인 수정·폐기 경로가 함께
   바뀝니다.

4. **USD에서만 동작하는 공개 코드는 지역에 따라 쓸 수 없어** 마케팅·지원 비용을
   만듭니다. 이번 사건이 그 형태였습니다.

5. **현재 확인된 고정액 요구는 실제 캠페인이 아니라 테스트 코드**
   (`PAYMENTTEST27`)입니다. §6에서 이 전제를 확인합니다.

### 3.1 정률이 대체하지 **못하는** 경우

정률로 충분한 것은 목적이 "몇 % 할인"일 때입니다. 목적이 **"첫 달을 각 시장의
특정 금액으로 판매"** 라면 정률은 대체재가 아닙니다.

`discountPercent`는 `Int`입니다(Prisma `Int @default(0)`, Admin schema
`z.number().int().min(0).max(100)`). 따라서 $15를 정확히 $1.00으로 만드는
93.333…%는 **표현할 수 없습니다.**

| | 결과 |
|---|---|
| $14 고정액 off $15 | **$1.00** |
| 93% | $1.05 |
| 94% | $0.90 |
| A$23의 93% | A$1.61 |
| €14의 93% | €0.98 |

이 경우에만 다중 통화 고정 프로모션을 도입할 사업적 이유가 생깁니다. §5가 그
조건입니다.

## 4. 기존 고정액 코드의 처리

컬럼과 기존 코드는 남기되, **범위를 넓히는 편집은 막고 좁히는 편집은 허용**합니다.
"편집 허용"으로 두면 신규 생성 차단이 우회됩니다.

| 동작 | 허용 |
|---|---|
| 신규 고정액 프로모션 생성 | **금지** |
| 비활성 고정액 코드 재활성화 | **금지** |
| 기존 고정액의 할인액 인상 | **금지** |
| 기존 고정액의 대상 플랜 추가 | **금지** |
| 기존 고정액의 기간 연장 (종료일 연기, 상환 상한 인상) | **금지** |
| 기존 코드 비활성화 | 허용 |
| 기존 코드 종료일 단축 | 허용 |
| 정률로 전환 | **기존 코드를 변형하지 말고 새 코드 생성** |

기존 활성 코드는 **USD-only로 명시**하고 만료까지 유지합니다. 마케팅·지원 문구에
그 제약이 드러나야 합니다.

마지막 항목이 중요합니다. 고정액 코드를 정률로 "바꾸면" 같은 코드 문자열이
시점에 따라 다른 할인을 뜻하게 되고, 이미 상환된 기록과 대조가 안 됩니다.
`pricingVersion`을 snapshot에 저장하고 가격 변경을 소급 적용하지 않는 기존 규율
(`docs/policy/credit-and-cost-limits.md`)과 같은 이유입니다.

## 5. `discountAmountCents` 컬럼

**당장 삭제하지 않습니다.** 과거 감사 데이터가 참조합니다 —
`BillingPromotionRedemption`은 상환 시점의 프로모션을 가리키고, 그때 어떤 할인이
적용됐는지는 재구성할 수 있어야 합니다.

삭제는 아래를 모두 확인한 뒤 **별도 migration**으로 합니다.

1. 활성 고정액 코드 0개
2. 예약(미시작) 고정액 코드 0개
3. 과거 데이터 의존성 없음 — 감사·정산·리포트 어느 경로도 이 컬럼을 읽지 않음

## 6. Rollout 조건 — production inventory

**아래를 확인하기 전에는 Admin 차단을 배포하지 않습니다.** 읽기 전용 조사입니다.

- 활성 고정액 코드의 수와 목록
- 각 코드의 캠페인 소유자, 노출 국가, 종료일
- 예약(startsAt 미래) 및 만료 고정액 코드

결과에 따라 갈립니다.

- **활성 0개**: 신규 생성과 재활성화를 즉시 차단하고 컬럼을 deprecated 처리할 수
  있습니다.
- **활성 있음**: 코드별로 소유자·노출 국가·종료일을 확인하고 전환 계획을 세운 뒤
  차단합니다. 차단이 진행 중인 캠페인의 운영을 막아서는 안 됩니다.

차단은 **Admin UI뿐 아니라 Admin API에서도** 적용합니다. UI만 막으면 API가 우회
경로가 됩니다.

## 7. 향후 도입 조건

다중 통화 고정액을 도입하려면 **모두** 충족해야 합니다.

1. 실제 캠페인 요청이 존재할 것 — "첫 달 A$1 / €1 / ₩1,000" 같은, 시장별 목표
   금액이 사업적으로 정해진 요청. 테스트 코드나 가정은 근거가 되지 않습니다.
2. **finance-ops가 각 통화의 값을 승인**할 것. 승인 주체는 finance-ops이며,
   승인 없이는 어떤 값도 저장하지 않습니다.
3. 캠페인 수정·폐기와 Stripe 쿠폰 버전 관리 절차가 함께 정해질 것.

### 7.1 표현 형태

도입한다면 `discountAmountByCurrency`보다 캠페인의 본뜻을 담는 형태를 검토합니다.

```
targetPriceByCurrency:
  USD: 100
  AUD: 100
  EUR: 100
  KRW: 1000
  CNY: 500
```

"얼마 할인"이 아니라 **"최종 얼마에 판매"** 하는 캠페인이라면 이 표현이 더
정확합니다. 요금제 가격이 바뀌면 할인액은 의미를 잃지만 목표가는 유효합니다.

절대 조건:

- **승인된 시장별 값만 사용합니다.** 환율로도, 가격 비율로도 값을 생성하지
  않습니다. 그 생성이 이 문서를 만든 사건입니다.
- 값이 없는 통화는 **적용 불가**입니다. 비워 두고 다른 통화에서 유도하지
  않습니다.
- plan · billing interval · **가격 버전(`pricingVersion`)별로 범위를
  제한**합니다. 목표가는 특정 가격표 위에서만 뜻이 있습니다.
- Stripe에는 해당 시점의 `amount_off`로 변환해 **별도 쿠폰 버전**을 생성합니다.
  Stripe는 `currency_options`로 통화별 할인액을 지원하지만 **자동 환산이
  아니며**, 쿠폰의 금액·통화 속성은 생성 후 변경에 제약이 있습니다. 값이 바뀌면
  새 쿠폰이고, 그 버전 관리는 운영 절차입니다.

## 8. 이 문서가 다루지 않는 것 — 가격 카탈로그 override

사고 화면의 Pro 월간은 **A$20.00**이었고 코드의 기본 카탈로그는 **A$23.00**
입니다. `AppSetting`의 `billingPriceCatalog`가 override하고 있으며 Admin
(`app/api/admin/billing/route.ts`)이 읽고 씁니다.

이는 **프로모션 정책과 별개인 가격 거버넌스 문제**입니다. 병렬로 확인하되 §2의
결정을 막지 않습니다.

확인할 것: override의 현재 값, 변경 주체, 적용 시각, 승인 근거. Checkout이 실제로
청구하는 금액은 override 값입니다.

**확인 전에 A$23으로 되돌리지 않습니다.** 승인 기록이 없다는 사실만으로 되돌리면
그 자체가 실제 가격 인상이 됩니다.

## 9. 이미 반영된 것

이 문서의 결정과 별개로, 계약 불일치는 수정돼 배포 경로에 올라 있습니다.

- 통화 판정이 `promotionCurrencyFailure()` 한 곳에 있고,
  `validatePromotionForCheckout()`이 `currency`를 필수 인자로 받습니다.
- validation이 Checkout과 같은 `validateBillingMarketRequest()` 계약을 씁니다.
- Checkout이 같은 검사를 Stripe·lease·redemption **이전에** 재실행합니다.
- 거절은 `PROMOTION_CURRENCY_NOT_SUPPORTED`이고 7개 언어로 현지화됩니다.
- 주문 요약은 청구 가능한 프로모션만 그립니다.

즉 **오늘도 비 USD 고정액 코드는 사용할 수 없습니다.** 이 문서는 그 상태를 정책
으로 확정하고 확장하지 않기로 하는 것이지, 되던 것을 막는 것이 아닙니다.
