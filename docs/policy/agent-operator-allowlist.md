# Agent 정책 승인자 목록

version: 1 · owner: Tomverse Pty Ltd · approvedBy: mposition · approvedAt: 2026-09-21

## 1. 이 파일이 정하는 것

`docs/policy/<agent>.md`의 `approvedBy`에 적힐 수 있는 **계정의 닫힌 목록**입니다.
여기 없는 계정이 적힌 정책 문서는 승인된 것이 아니며, 그 정책에 기대는 구현은
착수 조건을 충족하지 못합니다.

이 파일은 **권한을 주지 않습니다.** GitHub 권한, 병합 권한, 배포 권한은 저장소
ruleset과 조직 설정이 정합니다. 이 목록은 "승인이 실제로 일어났는가"를 기록만으로
판정할 때 쓰는 **대조 대상**입니다.

## 2. 목록

| 계정 | 역할 | 등재일 |
|---|---|---|
| `mposition` | 운영자 (Tomverse Pty Ltd) | 2026-09-21 |

**현재 1인 조직입니다.** 승인자와 증거 작성자가 분리되지 않는다는 뜻이 아닙니다 —
증거는 대개 자동화가 만들고, 승인은 사람이 합니다. 두 번째 담당자가 생기면 행을
추가하고 §3 절차로 병합합니다.

## 3. 이 파일을 바꾸는 방법

이 파일의 변경은 **정책 승인과 같은 판정**을 받습니다. 판정 절차는
`docs/policy/<agent>.md`가 인용하는 7단계이며, 차이는 하나입니다.

- **대조 대상이 이 PR의 base에 있던 이전 목록입니다.** 새 목록으로 자기 자신을
  정당화할 수 없습니다. 계정을 추가하는 PR은 **추가되기 전 목록에 이미 있던**
  계정이 승인하고 병합해야 합니다.
- `version`을 반드시 올립니다. 올리지 않은 변경은 판정에서 거절합니다.
- 이 파일 하나만 바꿉니다. 다른 변경을 함께 담지 않습니다.
- 브랜치 이름에 `to-develop` 경로 조각을 넣지 않습니다. 넣으면 자동 PR과
  auto-merge가 붙어 사람이 병합했다는 증거가 사라집니다.

**Agent는 이 파일을 바꾸지 않습니다.** 두 규칙이 함께 이것을 막습니다 — Agent는
자기 자신을 통과시키는 gate를 고칠 수 없고, `docs/policy/**`는 어떤 Agent의 쓰기
허용 목록에도 들어가지 않습니다. 초안을 제안하는 것까지가 Agent의 몫이고, commit과
병합은 사람의 행위입니다.

## 4. genesis

이 파일의 **최초 commit SHA**가 판정의 출발점입니다. 각 Agent 정책 문서는 그 SHA를
`allowlistGenesisCommit:` 줄에 적고, 판정은 그 SHA에서 현재까지의 변경을 §3으로
따라옵니다.

출발점은 순환을 끊기 위해 **사람이 직접 찍습니다.** genesis commit의 작성자와
병합자가 모두 `mposition`이어야 하고, 그 PR은 이 파일 하나만 담습니다.

## 5. 이 판정이 못 하는 것

**이 저장소에서 일하는 Agent 세션은 `mposition` 명의로 commit하고, 그 계정의
GitHub 토큰도 함께 씁니다.** 그래서 규칙을 어기고 만든 commit은 이 판정으로
구별되지 않습니다.

**이 판정이 증명하는 것은 절차이지 작성자가 아닙니다.** 브랜치 이름이 맞았는지,
PR이 하나였는지, 정책 파일만 바뀌었는지, 날짜가 병합과 맞는지 — 실수와 우회는
잡습니다. "정말 사람이 했는가"는 잡지 못합니다.

그것까지 잡으려면 **Agent가 쓸 수 없는 서명 키**(터치가 필요한 하드웨어 키를
`mposition`의 signing key로 등록)가 필요하고, 판정도 "그 키로 서명된 commit"을
요구하도록 바뀌어야 합니다. **오늘은 하지 않았습니다.** 하지 않았다는 사실을
여기 적어 두는 것이 이 절의 목적입니다.
