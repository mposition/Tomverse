# 제품 경계 v1.2 staging 검증 실행 기록

`../product-boundary-v1-2-staging-checklist.md`는 항목만 가진 template입니다.
실행 결과는 여기에 **실행 1회 = 파일 1개**로 남습니다.

규칙은 외부 import·이미지 생성·생성 파일·assistant profile·assistant
knowledge·채팅 첨부 기록과 같습니다. 일곱 번째로 같은 규칙을 적는 이유도 같습니다
— 이 구조가 만들어진 계기가 **문서 하나가 낡은 채로 공식적으로 보였던 일**이기
때문입니다.

## 파일 이름

```
YYYY-MM-DD__<40자리 deploy SHA>.md
```

전체 SHA를 씁니다. 축약 SHA는 시간이 지나면 충돌할 수 있고, 무엇보다 어느
커밋인지 확인하려면 저장소를 뒤져야 합니다.

## 규칙

1. **기록은 덮어쓰지 않습니다.** 재검증은 새 파일입니다.
2. **비어 있던 항목을 나중에 통과로 채우지 않습니다.** 실행하지 않은 항목은
   `미기록`이며, 그것이 사실입니다.
3. **한 기록은 자기가 실행된 template revision을 적습니다.**
4. **동결된 기록은 digest로 보호합니다.** `frozen: true`인 기록은
   `npm run check:staging-verification-records`가 본문 digest를 대조합니다.
5. **실행·판정·서명은 사람이 합니다.** 통과·조건부·실패의 **판정**과 **서명**은
   사람만 씁니다. 관측을 옮겨 적는 것은 에이전트가 합니다 — 경계는 **관측과
   판정**입니다. "행이 0건이었다"는 관측이고, "그러므로 배포해도 된다"는
   판정입니다. 지어낸 관측은 어느 쪽에서도 허용되지 않습니다.

## 이 기능에만 있는 규칙

6. **A-1은 production을 읽습니다.** 이 체크리스트에서 유일하게 staging이 아닌
   데이터베이스를 보는 항목이고, 그래야만 답이 나오기 때문입니다 — 인덱스 락이
   문제가 되는지는 production의 `RoutingRun` 크기가 정합니다. **읽기만 합니다.**
   기록에는 행 수와 평소 분당 턴 수를 적습니다.

7. **A-1의 판정을 기록하지 않은 회차는 배포 근거가 되지 못합니다.** 이 회차
   전체가 존재하는 이유가 "이 마이그레이션을 그대로 배포해도 되는가" 하나이고,
   나머지 항목은 전부 그 다음 질문입니다. 행 수를 적지 않은 기록은 그 질문에
   답하지 않은 기록입니다.

8. **P-1에는 숫자를 적지 않습니다.** Search Console 실적을 이 저장소에 옮겨
   적을 이유가 없습니다. **저장한 위치와 시각**만 적습니다.

9. **flag를 켜지 않았다는 것을 적습니다.** 이 회차에서
   `TOMVERSE_AUTO_ROUTER_UI_ENABLED`와 세 readiness gate는 건드리지 않습니다.
   켠 채로 실행한 회차는 다른 것을 검증한 것이며, 그 사실이 기록에 없으면
   나중에 알 수 없습니다.

10. **정리 의무.** staging에서 만든 계정·대화·이미지·공유 링크는 회차가 끝나면
    지웁니다. 지우지 못한 것이 있으면 기록에 남깁니다 — 다음 회차의 `B-2`가
    "배포 이전부터 있던 대화"를 필요로 하므로, 무엇이 남아 있는지가 다음 실행의
    전제가 됩니다.
