# 채팅 첨부 형식 staging 검증 체크리스트

`docs/policy/chat-attachment-formats.md`가 정한 계약을 staging에서 확인하는
항목입니다. 대상은 ZIP 압축파일, 정지 GIF, 소스코드·마크업·데이터 형식, 그리고
Office 97-2003·RTF입니다.

실행·판정·서명은 사람이 합니다. 에이전트는 항목을 갱신할 수 있지만 실행 결과를
스스로 기입할 수 없습니다.

## 이 문서는 template입니다

**여기에는 결과가 없습니다.** 체크박스는 항상 비어 있고, 그것이 이 파일의
상태입니다. 실행 결과는 `chat-attachment-staging-verification-records/`에
**날짜와 전체 deploy SHA로 이름 붙인 별도 파일**로 남습니다.

- **template revision**: `2026-08-22a` — 항목이 바뀌면 이 값을 올리고, 실행
  기록은 자기가 어느 revision으로 실행됐는지 적습니다.
- 실행 방법과 파일 이름 규칙:
  `chat-attachment-staging-verification-records/README.md`
- 기록 template:
  `chat-attachment-staging-verification-records/_record-template.md`

## 릴리스 차단 항목은 없습니다

`AGENTS.md`의 기준 — **무엇이 복구 불가인지 한 줄로 적을 수 없으면 차단이
아니다** — 로 이 변경을 하나씩 확인한 결과입니다.

| 후보 | 왜 차단이 아닌가 |
|---|---|
| finalize가 검증 실패 객체를 삭제 | 원본은 사용자 기기에 있다. 다시 올리면 된다 |
| 압축 내부 PDF의 OCR 비용 | 잘못된 과금은 환급된다 |
| 압축 내부 경로가 프롬프트에 들어감 | 사용자 자신의 경로이고, 오류·로그에는 실리지 않는다 |
| 새 파서의 오독 | 고쳐서 배포하면 끝난다. 이력 테이블이 사라지지 않는다 |

schema 변경, `Conversation.selectedModels` 쓰기, pin된 version 쓰기, 소유권
판정 변경이 **하나도 없습니다.** 그래서 이 검증은 flag를 켜기 위한 전제
조건이 아니라, **되돌릴 수 있는 것을 배포 전에 싸게 발견하기 위한** 것입니다.
사람이 범위를 줄이면 그대로 따르고, 건너뛴 구획은 기록의 `미기록`입니다.

## 필수는 3항목, 유료 2 turn

**이것만 하면 이 회차는 성립합니다.**

| 항목 | 무엇을 판별하는가 | 비용 |
|---|---|---|
| **B-2** | 압축 내부 텍스트가 실제로 모델 답에 도달하는가 | 유료 1 turn |
| **C-2** | 자체 파서가 **진짜 MS Office 파일**을 읽는가 | 유료 1 turn |
| **E-1** | 실기기 파일 선택기의 MIME 보고 — 고치려던 회귀 | 무료 |

`A-1`(배포 SHA 기록)은 항목이 아니라 기록의 전제이고, `B-1`·`C-1`은 B-2·C-2를
하려면 지나야 하는 업로드 단계입니다. 따로 세지 않습니다.

나머지 D·F·G·H와 B-3·C-3·D-2·E-2는 **선택**입니다. 하면 좋지만, 안 해도 이
회차는 유효하고 건너뛴 것은 기록의 `미기록`입니다.

## 시료는 만들어져 있습니다

```
node scripts/make-chat-attachment-staging-kit.mjs
```

zip(제외 2건 포함), 정지·애니메이션 GIF, 파일 선택기용 `.md`·`.csv`·`.json`·
`.py`, 8.5MB 파일, 한국어 `.doc`·`.xls`·`.ppt`·`.rtf`, 그리고 **정답지**
(`MANIFEST.md` — 무엇이 읽혀야 하고 무엇이 왜 빠져야 하는지)를 만듭니다. 손으로 준비할 것이 아닙니다:
`AGENTS.md`의 "사람에게 남기는 것은 사람만 할 수 있는 것뿐입니다".

**kit이 만들지 못하는 것은 셋뿐이고, 그래서 그 셋이 사람 몫입니다.**

- **Microsoft Word가 저장한 `.doc`** — C-2용. kit의 LibreOffice 파일은 배선을
  보고, 이건 파서가 Word의 바이트 배치를 읽는지를 봅니다. 다른 주장입니다.
- **암호가 걸린 legacy 문서** — C-3용(선택). LibreOffice는 legacy 필터의
  `Password=`를 받고도 암호화하지 않은 파일을 씁니다.
- **실기기와 그 OS의 파일 선택기** — E-1용.

## CI가 증명하는 것은 여기 없습니다

항목을 늘리려는 사람은 먼저 물어야 합니다 — **이것을 CI가 증명하지 못하는
이유가 무엇인가.** 답할 수 없으면 그 항목은 test에 속하지 이 문서에 속하지
않습니다.

| CI가 이미 증명하는 것 | 어디서 |
|---|---|
| 형식 판정 행렬(빈 MIME, 별칭, 불일치, 확장자 없음) | `tests/chatAttachmentFormats.test.mjs` |
| ZIP 거절 전량(암호화·ZIP64·traversal·폭탄·심볼릭 링크·중복·실행파일·개인키) | `tests/chatArchivePlan.test.mjs` |
| 압축 해제와 디렉터리/스트림 크기 대조 | `tests/chatArchive.test.mjs` |
| 텍스트 디코딩(BOM·UTF-16·NUL·깨진 인코딩) | `tests/chatAttachmentText.test.mjs` |
| GIF 프레임 판정과 애니메이션 거절 | `tests/gifStructure.test.mjs`, `tests/chatAttachmentValidation.test.mjs` |
| 레거시 파서 정상·거절 경로(실제 문서 fixture) | `tests/legacyOfficeText.test.mjs` |
| 오류 코드 → 7개 locale 문구 | `tests/chatAttachmentErrorCopy.test.mjs` |
| composer 계약·업로드 UI·오류 표시 | `tests/e2e/attachment-flow.spec.ts`, `mobile-composer-contract.spec.ts` |

**CI가 증명하지 못하는 것**이 이 체크리스트의 전부입니다.

1. **실제 R2 왕복** — CI의 업로드 경로는 mock입니다. finalize가 객체를 되읽는
   비용과 지연은 staging에서만 관측됩니다.
2. **실제 공급자 응답** — GIF에서 만든 PNG를 공급자가 실제로 받는지, 압축 내부
   텍스트가 모델의 답에 실제로 반영되는지.
3. **실제 브라우저·OS의 MIME 보고** — Playwright는 `File`을 합성하므로 Windows·
   Android 파일 선택기가 MIME을 비워 보내는 그 상황 자체는 재현되지 않습니다.
   이 회귀가 이 작업의 출발점 중 하나였습니다.
4. **게스트 Turnstile과 객체 TTL** — CI는 둘 다 우회합니다.

## 실행 순서

**필수 3항목만 하는 경로.** 시료는 kit이 이미 만들어 두었고, 사람이 준비할
것은 진짜 MS Office 파일 하나뿐입니다.

| | 하는 일 | 비용 |
|---|---|---|
| **1** | `GET /api/build-info`의 40자리 SHA를 기록에 적는다 (A-1) | 0 |
| **2** | `ledger-source.zip` 첨부 → 업로드 성공, 제외 안내가 **2** (B-1) | 0 |
| **3** | 그대로 "이 압축파일에 어떤 파일이 있고 각각 무슨 내용인지 알려줘" **1 turn** (B-2) | 유료 |
| **4** | kit의 `policy-libreoffice.doc` 첨부 → 업로드 성공 (C-1) | 0 |
| **5** | **Word가 저장한** `.doc`으로 **1 turn** → 답이 실제 내용을 인용 (C-2) | 유료 |
| **6** | 실기기 파일 선택기로 `picker-limits.csv` 골라 업로드 (E-1) | 0 |
| **7** | 판정 → 정리 → 서명 | 0 |

2·3의 판정 근거는 kit의 `MANIFEST.md`에 있습니다 — 읽혀야 하는 파일 5개와
제외돼야 하는 2개가 이름으로 적혀 있고, 답이 `Main.class`나 `.pyc`를 있다고
말하면 실패입니다.

**3에서 실패하면 5로 가지 마세요.** 고친 뒤 다시 시작하는 편이 쌉니다.

**6은 Windows에서 하시면 2와 같이 처리됩니다** — 어차피 그 기기에서 브라우저를
쓰고 계시면 파일 선택기로 고르는 것이 기본 동작입니다. 기록에 기기·OS·브라우저를

## A. 사전 조건 (무료, 3항목)

- [ ] A-1. `GET /api/build-info`가 돌려주는 40자리 SHA를 기록에 적었다.
- [ ] A-2. `attachmentsEnabled`가 켜져 있고, 시작 시점 값을 기록했다.
- [ ] A-3. staging의 R2 bucket이 production과 분리돼 있음을 확인했다.

## B. ZIP — 이 작업의 출발점 (유료 1 turn, 3항목)

무엇을 판별하는가: **압축 내부 텍스트가 실제로 모델의 답에 도달하는가.** 단위
테스트는 추출까지만 증명하고, 프롬프트 조립과 공급자 전송은 증명하지 않습니다.

- [ ] B-1. 소스 zip(텍스트·코드 여러 개 + 읽을 수 없는 파일 하나)을 첨부했고,
      업로드가 성공했으며 **제외 개수 토스트**가 실제 제외 수와 일치했다.
- [ ] B-2. **(유료)** "이 압축파일에 어떤 파일이 있고 각각 무슨 내용인지
      알려줘"로 1 turn 전송했고, 답이 **읽힌 파일만** 나열하며 내용이 실제와
      맞았다. 제외된 파일을 있다고 말하지 않았다.
- [ ] B-3. 같은 zip을 다시 첨부했을 때 업로드가 재현 가능했다(결정적 순서).

## C. 레거시 Office·RTF (유료 1 turn, 3항목)

무엇을 판별하는가: **자체 파서가 실제 사용자 문서에서도 동작하는가.** 이 구획은
두 개의 다른 주장으로 나뉘고, 한쪽만 사람 몫입니다.

- **배선** — 업로드 → R2 → finalize → 파서 → 프롬프트가 legacy 형식에 대해
  배포된 빌드에서 동작하는가. CI는 파서만 단독으로 돌리므로 이 경로를 지나지
  않습니다. **kit의 `policy-libreoffice.*` 넷이 이걸 봅니다.**
- **바이트 배치** — 파서가 **Word 자신이 쓴** 배치를 읽는가. Word가 저장한
  파일로만 확인됩니다. **이것만 사람 몫입니다.**

- [ ] C-1. kit의 `policy-libreoffice.doc`·`.xls`·`.ppt`·`.rtf`를 각각 첨부해
      업로드가 성공했다. (배선)
- [ ] C-2. **(유료)** **Microsoft Word가 저장한** `.doc` 하나로 1 turn
      전송했고, 답이 문서의 실제 내용을 인용했다(한국어 문단 포함).
      **LibreOffice로 만든 파일이 아니어야 합니다.**
- [ ] C-3. 암호가 걸린 문서를 첨부해 **"암호가 걸린 문서입니다…"** 문구가
      나왔다(0크레딧, 업로드에서 끝남). kit에 없습니다 — Word에서 정보 →
      문서 보호 → 암호 설정.

## D. GIF — 선택 (유료 1 turn, 2항목)

무엇을 판별하는가: **GIF에서 만든 PNG를 공급자가 실제로 받는가.** 정규화는
단위 테스트가 증명하지만, 공급자 수용은 증명하지 않습니다.

- [ ] D-1. **(유료)** 정지 GIF를 이미지 입력 모델에 첨부해 1 turn 전송했고,
      답이 이미지 내용을 설명했다.
- [ ] D-2. 애니메이션 GIF를 첨부해 **"애니메이션 GIF는 지원하지 않습니다…"**
      가 나왔다(0크레딧).

## E. 실제 브라우저의 MIME 보고 (무료, 2항목)

무엇을 판별하는가: **CI가 재현할 수 없는 회귀.** Playwright는 `File`을
합성하므로 OS 파일 선택기의 실제 동작은 여기서만 관측됩니다.

- [ ] E-1. **Windows 또는 Android 실기기**에서 `.md`·`.csv`·`.json` 중 하나를
      파일 선택기로 골라 업로드가 성공했다. 어느 기기·브라우저인지 적었다.
- [ ] E-2. 같은 기기에서 `.py` 같은 코드 파일을 골라 업로드가 성공했다.

## F. 게스트 — 선택 (유료 1 turn, 2항목)

무엇을 판별하는가: **Turnstile과 ephemeral 객체 경로.** CI는 둘 다 우회합니다.

- [ ] F-1. 로그아웃 상태에서 zip을 첨부해 업로드가 성공했고, 게스트 한도(파일
      5개까지 분석)가 안내와 일치했다.
- [ ] F-2. **(유료)** 게스트로 1 turn 전송해 답이 압축 내용에 근거했다.

## G. 기존 형식 회귀 — 선택 (무료, 1항목)

- [ ] G-1. PDF·PNG·DOCX·XLSX를 각각 첨부해 업로드가 성공했다. 전송은 하지
      않습니다 — 전송 경로는 B·C·D가 이미 지납니다.

## H. 관측 — 선택 (무료, 2항목)

무엇을 판별하는가: **finalize가 객체를 되읽게 된 비용.** 정확성이 아니라
지연과 요청 수의 문제이고, 실제 R2에서만 보입니다.

- [ ] H-1. 10MB에 가까운 파일 업로드의 finalize(PATCH) 응답 시간을 3회 재어
      기록했다.
- [ ] H-2. 업로드 1건당 R2 Class B 요청 수가 예상(HEAD + GET, 이전 대비 +1
      GET)과 일치함을 Cloudflare 지표에서 확인했다.

## 무엇이 배포를 막고, 무엇이 막지 않는가

**막는 것 — 이 셋 중 하나라도 실패하면 되돌리기 전에 고칩니다.**

- B-2가 실패했다 — 압축 기능이 광고한 일을 하지 않는 것입니다.
- C-2가 실패했다 — 레거시 형식을 "지원한다"고 표시하면서 읽지 못하는 것이고,
  이 정책이 금지하는 가짜 지원 그 자체입니다.
- E-1이 실패했다 — 고치려던 회귀가 그대로인 것입니다.

**막지 않는 것 — 기록하고 후속 티켓으로 넘깁니다.**

- 추출 품질이 아쉽다(표 정렬, 슬라이드 순서, 숫자 서식). 고쳐서 배포하면
  됩니다.
