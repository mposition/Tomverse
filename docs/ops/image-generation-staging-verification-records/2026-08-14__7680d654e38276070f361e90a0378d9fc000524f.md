### 발견 사항

1. **카탈로그 크레딧이 하한임이 화면에 드러나지 않음 (개선 필요)** — 탭은
   `Math.min(...prices)`로 "N크레딧부터"를 의도하나 "부터"가 접근성 라벨에만
   있다. GPT Image 2가 탭에서 15, 컴포저에서 70으로 보여 다른 가격으로 읽힌다.
   숫자 규칙 자체는 계약대로다.
2. **fal 정산 원가가 실제 청구보다 2,000µUSD 적게 기록됨** —
   `settledCostMicroUsd`는 이미지당 80,000이나 실제 청구는 82,000
   (high thinking 할증 $0.002, 2026-08-14 smoke test의 `x-fal-billable-units: 1.025`로
   실측). 사용자 과금은 고정 120크레딧이라 영향 없으나, provider 예산 집계가
   실지출을 약 2.5% 적게 센다.
3. **openai·xai 예산의 월 한도가 일 한도와 동일** — admin이
   `month_not_above_day` advisory를 스스로 보고한다. 하루만 한도까지 쓰면 그
   달이 소진된다. fal은 12M/50M으로 정상. 기존 staging 설정이며 이번 작업과
   무관.
4. **openai 정산 원가는 출력 원가 + 실측 프롬프트 토큰 비용** — registry의
   `outputCostMicroUsd`(53,000)와 정산 증가분(53,060)이 다른 것은 정상이다.
   fal은 이미지 단위 과금이라 정확히 80,000. 검증 기대값을 세울 때 registry
   값을 정산 총액으로 읽으면 안 된다.
5. **`budget.usedTodayMicroUsd`는 openai 전용 legacy 집계** — 조회 키가
   `image-provider:openai`로 고정돼 있다(`app/api/admin/image-generation/route.ts`).
   fal·xai 지출은 포함되지 않으므로 전체 이미지 지출로 읽으면 안 된다. 이번
   실행에서 +46,060 증가해 openai 정산 증가분 53,060과도 일치하지 않았고, 예약과
   정산 시점 차이로 보이나 **확인되지 않았다.** provider별 귀속은
   `providerBudgets`와 `settledByProviderModel`이 정확하다. 별도 조사 대상.
6. **`dimensionCoverage`에서 openai는 5건 중 4건만 측정됨** — 이번 실행 이전부터
   있던 상태이며 fal·xai는 전건 측정. 원인 미확인.
