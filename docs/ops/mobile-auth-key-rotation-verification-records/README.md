# 모바일 인증 키 회전 실행 기록

`../mobile-auth-key-rotation-checklist.md`는 항목만 가진 template입니다. 실행 결과는
여기에 **실행 1회 = 파일 1개**로 남습니다.

기계는 다른 검증 기록들과 같은 것을 씁니다 — 같은 생성기, 같은 검사기, 같은 파일 이름
규칙. **복사해서 두 번째 체계를 만들지 않는 이유**는 그 복사본이 뒤처지기 때문이고,
이 구조가 생긴 계기가 정확히 그것입니다.

**다른 점은 대상입니다.** 나머지는 배포된 코드를 staging에서 확인한 기록이고, 이것은
**운영자가 수행한 절차**의 기록입니다. 그래서 회전하지 않고 §2.1 검사만 돌린 회차도
기록 대상입니다 — §A만 채우고 나머지는 `미기록`입니다.

## 파일 이름

```
YYYY-MM-DD__<40자리 SHA>.md
YYYY-MM-DD__<40자리 SHA>__<실행 라벨>.md
```

여기서 SHA는 **그 실행 시점에 대상 배포가 서빙하고 있던 커밋**입니다. 로컬에서 검사만
돌린 회차라면 그 검사가 읽은 저장소의 `HEAD`이고, 어느 쪽인지 실행 환경 표에 적습니다.

**같은 날 같은 SHA로 두 번 실행하는 일은 실제로 생깁니다** — 변수 하나를 고치고 다시
검사하면 날짜도 SHA도 그대로입니다. 그때 두 번째 회차는 `--run`으로 라벨을 붙입니다
(`2`, `after-fix`처럼 짧게). 라벨이 없으면 생성기가 **거절하고 이 방법을 알려 줍니다** —
덮어쓰기는 하지 않습니다.

## 규칙

1. **기록은 덮어쓰지 않습니다.** 재실행은 새 파일입니다.
2. **비어 있던 항목을 나중에 통과로 채우지 않습니다.** 실행하지 않은 항목은 `미기록`
   이며, 그것이 사실입니다.
3. **한 기록은 자기가 실행된 template revision을 적습니다.**
4. **동결된 기록은 digest로 보호합니다.** `frozen: true`인 기록은
   `npm run check:staging-verification-records`가 본문 digest를 대조합니다.
5. **관측과 판정을 분리합니다.** "`sign-1`이 `RETIRED, 412 s left`로 나왔다"는 관측이고,
   "그러므로 승격한다"는 판정입니다. 관측은 에이전트가 옮겨 적을 수 있고 — 사람이
   실행하며 보고한 것을 표에 채우는 것은 사람에게 되받아 타이핑시키지 않기 위한
   일입니다 — **판정과 서명은 사람만 씁니다.** 지어낸 관측은 어느 쪽에서도 허용되지
   않으며, 초안은 그것이 초안임을 문서 안에서 밝히고 실행자가 각 줄을 확인한 뒤 commit
   합니다.

## 이 기능에만 있는 규칙

6. **비밀값을 적지 않습니다.** 서명 키 링, pepper 링, access token, refresh token,
   `secretDigest`, 그리고 `MOBILE_AUTH_*`의 원문 값은 어떤 칸에도, 어떤 발췌에도
   넣지 않습니다. 적는 것은 **key id, 종료 코드, 검사기가 출력한 상태 단어, 남은 초,
   감사 행의 `event`·`reason`, deployment ID**입니다.

   두 wrapper는 길이만 출력하므로 그 출력은 그대로 붙여도 안전합니다. 그것이 붙여도
   되는 유일한 이유이고, 다른 곳에서 복사한 발췌는 붙이기 전에 눈으로 봅니다.

7. **미판정을 통과로 적지 않습니다.** §3의 8번이 미판정으로 끝난 회차는 판정란이
   `미판정`이고, 무엇이 판정되지 않았는지를 함께 적습니다. 그 상태의 처리는 회전
   runbook §6의 6번이 정해질 때까지 사람에게 올리는 것입니다.

8. **이 기록은 §6의 5번(증거 결속)을 해결하지 않습니다.** SHA와 deployment ID를 적는
   것은 **무엇을 대상으로 실행했다고 사람이 말했는지**를 남기는 일이지, 수집된 증거가
   그 배포에서 나왔다는 **증명**이 아닙니다. 그 결속은 여전히 미결이고, 기록에 칸이
   생겼다는 이유로 닫힌 것처럼 쓰지 않습니다.

## 새 실행을 시작할 때

기록은 손으로 복사하지 말고 생성합니다.

```
npm run new:staging-verification-record -- --feature mobile-auth-key-rotation --sha <40자리 SHA>
npm run new:staging-verification-record -- --feature mobile-auth-key-rotation --sha <40자리 SHA> --run 2
```

체크리스트의 전 구획을 읽어 항목마다 한 행씩 펼친 빈 기록을 만듭니다. `--preview`를
붙이면 파일을 쓰지 않고 출력만 합니다. 이미 있는 파일은 덮어쓰지 않습니다.

## 실행 순서

1. 대상 배포가 서빙 중인 40자리 SHA를 확인합니다(`GET /api/build-info`). 로컬 검사만
   하는 회차라면 저장소의 `HEAD`를 씁니다.
2. 그 SHA로 기록을 생성합니다. **커밋하지 않은 상태로 둡니다.**
3. 절차를 수행하며 **명령·종료 코드·관측**을 그때그때 적습니다. 나중에 기억으로 채우면
   그것은 관측이 아닙니다.
4. 필수 항목에 `미기록`이 남아 있으면 전체 결과를 `통과`로 서명하지 않습니다.
5. 실행자·승인자가 서명합니다.
6. 최종 본문으로 digest를 계산하고 `frozen: true`와 함께 적습니다.

```
node scripts/check-staging-verification-records.mjs --digest <파일>
```

7. `npm run check:staging-verification-records`가 통과한 뒤에 커밋합니다.

**결과와 서명이 빈 기록을 커밋하거나 PR에 올리지 않습니다.** 검사기는 `frozen`이
아니어도 `executor`와 `result`를 요구하므로 빈 기록은 실패하고, 그것이 의도입니다.
