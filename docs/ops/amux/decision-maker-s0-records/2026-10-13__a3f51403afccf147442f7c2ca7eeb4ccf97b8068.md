## 계정을 만든 방식

root 셸에서 실행했다.

```bash
for u in amux-dm-broker amux-dm-openai amux-dm-anthropic; do
  useradd --system --create-home --home-dir "/home/$u" --shell /usr/sbin/nologin --user-group "$u"
  chmod 0700 "/home/$u"
done
usermod -aG amux-dm-openai,amux-dm-anthropic amux-dm-broker
install -d -o root -g root -m 0755 /var/lib/amux-dm
install -d -o amux-dm-broker -g amux-dm-broker -m 0711 /var/lib/amux-dm/requests
```

만든 뒤의 상태는 다음과 같다.

- `amux-dm-broker`의 그룹: `amux-dm-broker`, `amux-dm-openai`, `amux-dm-anthropic`.
- 두 DM 계정은 자기 그룹에만 속한다.
- 세 홈은 모두 `700`, 소유자는 각 계정이다.
- `/var/lib/amux-dm/requests`는 `711 amux-dm-broker:amux-dm-broker`다.

설정의 이유는 둘이다.

- **홈을 `0700`으로 둔다.** broker가 두 DM 그룹에 들어가므로, 기본값 `0750`이면 broker가 DM 홈을 읽는다.
- **요청 상위 디렉터리를 `0711`로 둔다.** DM 계정은 이 디렉터리를 지나 자기 요청 디렉터리에 닿아야 하고, worker와
  bridge는 그 안의 목록을 보지 못해야 한다.

## 네트워크를 막은 방식

**구조.** nftables 표 `inet amux_dm` 하나를 쓴다.

- **대상:** output hook에서 소켓 소유 UID가 DM 계정 둘이나 broker인 연결만 `restricted` chain으로 보낸다. 다른
  계정의 연결은 그대로 통과한다.
- **허용:** 각 계정은 자기 host의 IPv4 주소, TCP 443만 쓸 수 있다. 세 계정 모두 로컬 resolver(`127.0.0.53:53`)는 쓸 수
  있다.
- **거절:** 그 밖의 연결은 TCP reset이나 ICMP로 바로 거절한다. 거절하지 않고 버리면 연결 시도가 시간 초과까지
  매달려 control 검사가 실패한다.

**IP 목록 갱신.** host 이름은 실행할 때마다 IPv4로 다시 풀어 넣는다. systemd timer가 부팅 1분 뒤와 그 뒤 10분마다
실행한다.

**파일.** root 셸에서 아래 세 파일을 만들고 `systemctl start amux-dm-egress.service`와
`systemctl enable --now amux-dm-egress.timer`를 실행했다.

| 파일 | SHA-256 (호스트에서 확인) |
|---|---|
| `/usr/local/libexec/amux-dm-egress` (`0755`) | `f5a758646529c684fd2a93600401b400861e6a7fe603aed260a4abe8b8c0a976` |
| `/etc/systemd/system/amux-dm-egress.service` | `3c27a467b7e28d5d86a4de5de4336f1c467737ee9fd73bdfa5572c787b6c3ce9` |
| `/etc/systemd/system/amux-dm-egress.timer` | `d4f722bce6411627dc2ee29fac5664e11795190ef9032438c00f78bdf9b52abf` |

`/usr/local/libexec/amux-dm-egress`:

```bash
#!/bin/bash
# AMUX DM S0 egress: each DM account reaches only its vendor's hosts and the
# broker only GitHub's public hosts. Names are re-resolved on every run; a name
# that resolves to nothing leaves the previous table in place.
set -euo pipefail
v4() { getent ahostsv4 $1 | awk '{print $1}' | sort -u | paste -sd, -; }
OPENAI=$(v4 "api.openai.com chatgpt.com")
ANTHROPIC=$(v4 "api.anthropic.com")
GITHUB=$(v4 "api.github.com raw.githubusercontent.com")
for v in OPENAI ANTHROPIC GITHUB; do [ -n "${!v}" ] || { echo "amux-dm-egress: $v resolved to nothing" >&2; exit 1; }; done
U_OPENAI=$(id -u amux-dm-openai); U_ANTHROPIC=$(id -u amux-dm-anthropic); U_BROKER=$(id -u amux-dm-broker)
nft -f - <<NFT
table inet amux_dm {}
delete table inet amux_dm
table inet amux_dm {
  set openai { type ipv4_addr; elements = { $OPENAI } }
  set anthropic { type ipv4_addr; elements = { $ANTHROPIC } }
  set github { type ipv4_addr; elements = { $GITHUB } }
  chain output {
    type filter hook output priority filter; policy accept;
    meta skuid { $U_OPENAI, $U_ANTHROPIC, $U_BROKER } jump restricted
  }
  chain restricted {
    ip daddr 127.0.0.53 udp dport 53 accept
    ip daddr 127.0.0.53 tcp dport 53 accept
    meta skuid $U_OPENAI ip daddr @openai tcp dport 443 accept
    meta skuid $U_ANTHROPIC ip daddr @anthropic tcp dport 443 accept
    meta skuid $U_BROKER ip daddr @github tcp dport 443 accept
    meta l4proto tcp reject with tcp reset
    reject
  }
}
NFT
```

`/etc/systemd/system/amux-dm-egress.service`:

```ini
[Unit]
Description=AMUX DM egress rules
Wants=network-online.target
After=network-online.target nftables.service

[Service]
Type=oneshot
ExecStart=/usr/local/libexec/amux-dm-egress
```

`/etc/systemd/system/amux-dm-egress.timer`:

```ini
[Unit]
Description=Re-resolve AMUX DM egress hosts

[Timer]
OnBootSec=1min
OnUnitActiveSec=10min

[Install]
WantedBy=timers.target
```

## 관측 (판정하지 않음)

| 항목 | 값 | 뜻 |
|---|---|---|
| `workerSeesDmCmdline` | `allowed` | worker가 DM 프로세스의 command line을 읽을 수 있다. `/proc`에 `hidepid`가 없기 때문이다 |
| `ptraceScope` | `1` | |
| `procHidepid` | `none` | |

`workerSeesDmCmdline`이 `allowed`이므로 **S2의 전용 launcher argv에는 비밀값도 카드 내용도 넣을 수 없다.** 정책 §5는
이미 고정 argv와 고정 환경을 요구한다. 이 관측은 그 argv가 worker에게 보인다는 사실을 더한다.

## 이 측정이 증명하지 않는 것

1. **IP 기준 허용이다.** 허용한 IP를 같은 CDN에서 함께 쓰는 다른 사이트에도 DM 계정이 연결될 수 있다. 외부 도달 검사의
   표본은 `example.com` 하나다.
2. **DNS 질의는 막지 않았다.** 세 계정 모두 `127.0.0.53`에 질의할 수 있다.
3. **표는 부팅 뒤 timer가 처음 실행될 때까지(약 1분) 없다.** 그동안 세 계정의 연결은 막히지 않는다. 표는 nftables 설정
   파일에 저장되지 않는다.
   - 이름 해석이 실패하면 스크립트는 표를 바꾸지 않고 끝난다. 부팅 직후 첫 실행이 실패하면 다음 실행까지 표가 없다.
4. **`tommy`는 `adm` 그룹이라 시스템 로그를 읽을 수 있다.** S2에서 broker나 DM 프로세스의 출력이 journal에 남으면
   worker가 읽게 된다. 정책 §5는 DM 출력이 worker가 읽는 어떤 파일에도 쓰이지 않기를 요구한다.
5. **bridge 역할로는 `tomverse-bridge.service`의 계정만 쟀다.** v22 bridge와 sidecar unit(`tomverse-amux-v22-*@*`)의
   계정은 이 측정의 주체가 아니다.
6. **정책 §12 S0의 계정 격리 항목 하나만 다룬다.** 남은 S0 항목은 다음과 같다.
   - 두 CLI의 두 모델 가용성, 구조화 출력, 강제 종료, 재시도·중복 응답 형태. 유료 turn이 필요하다.
   - 고정 argv와 설정 digest, 명령 실행을 끄는 모드의 유무와 효과.
   - 두 공급사의 처리위탁 조건.
