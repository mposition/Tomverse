# AI 생성 파일(Generated Artifact) staging 검증 체크리스트

`docs/policy/generated-artifacts.md`가 요구하는 검증입니다. 구현과 자동 테스트는
끝났고, 남은 것은 **실제 배포에서 실제 파일이 실제로 열리는가**입니다.

로컬 테스트가 증명하지 못하는 것이 정확히 세 가지 있고, 이 문서는 그 세 가지를
위해 존재합니다.

1. **파일이 진짜 열리는가.** 로컬에서는 `officeparser`·`pdfjs-dist`·`fflate`로
   다시 읽어 봤습니다. 그것은 "파서가 읽는다"이지 "Excel이 연다"가 아닙니다.
   특히 **PDF의 한글**은 임베드가 잘못되면 틀린 글자가 아니라 **빈칸**으로
   나오고, 빈칸은 파서 검증을 통과합니다.
2. **저장소·권한이 실제로 붙어 있는가.** R2 왕복, 서명 없는 다운로드,
   소유권 조회, 잠금 grant는 mock으로는 서로 맞는 척할 수 있습니다.
3. **모델이 tool을 실제로 부르는가.** 로컬 테스트는 collector를 직접 호출합니다.
   provider가 이 schema를 보고 정말 호출하는지는 여기서만 드러납니다.

실행·판정·서명은 사람이 합니다. 에이전트는 항목을 갱신하고, 무인증 구획(§A)을
직접 실행하며, 실행자가 보고한 관측을 기록 초안에 옮겨 적을 수 있습니다. 쓸 수
없는 것은 **판정과 서명**뿐이며, 직접 보지도 보고받지도 않은 결과를 적는 것은
어느 쪽에서도 허용되지 않습니다 — 기록 README의 5번 참조.

## 이 문서는 template입니다

**여기에는 결과가 없습니다.** 체크박스는 항상 비어 있고, 그것이 이 파일의
상태입니다. 실행 결과는 `generated-artifacts-staging-verification-records/`에
**날짜와 전체 deploy SHA로 이름 붙인 별도 파일**로 남습니다.

- **template revision**: `2026-08-21` — 항목이 바뀌면 이 값을 올리고, 실행
  기록은 자기가 어느 revision으로 실행됐는지 적습니다.
- 실행 방법과 파일 이름 규칙:
  `generated-artifacts-staging-verification-records/README.md`
- 기록 template:
  `generated-artifacts-staging-verification-records/_record-template.md`

## 무엇에 대해 실행하는가

- **정식 실행(`formal`)**: production 활성화 후보 SHA 위에서만 성립합니다.
  `deploymentId`와 `appliedMigrations`를 함께 적습니다.
- **탐색 실행(`exploratory`)**: 아무 SHA에서나 해도 되지만 서명·동결하지 않고
  승인 근거가 되지 않습니다.

## 사전 조건

하나라도 어긋나면 검증이 아니라 **다른 것을 측정**하게 됩니다.

- [ ] staging이 서비스 중인 전체 40자리 deploy SHA를 확보했고 기록에 적었다
      (`GET /api/build-info`의 `commitSha`)
- [ ] `GET /api/ready`가 `ok: true`
- [ ] `MessageArtifact` migration이 적용됐다 (`appliedMigrations`에 적는다)
- [ ] 서로 다른 **로그인 계정 2개**를 준비했다 — §F가 이것 없이는 성립하지 않는다
- [ ] `ARTIFACT_TOOL_CAPABILITIES`에 있는 모델을 선택했다. 목록 밖 모델은
      fail-closed이므로 "tool을 안 부른다"가 정상 동작이고, 그것을 실패로
      읽으면 잘못된 결론이 난다
- [ ] **크레딧이 실제로 차감됩니다.** §B 이후는 전부 유료 실행입니다

## 무엇이 차단이고, 무엇이 아닌가

**12개 구획이 전부 릴리스 차단 사유는 아닙니다.** 목록만 보면 전부 그렇게
보이고, 그것이 1인 조직에서 검증을 감당 못 할 일로 만듭니다.

기준은 AGENTS.md의 것과 같습니다 — **틀렸을 때 되돌릴 수 없는가.**

### 차단 (production 공개 전에 반드시)

| 구획 | 왜 차단인가 |
|---|---|
| **A-3** `objectKey`·서명 URL 미노출 | 유출은 회수가 성립하지 않는다. 한 번 나간 키는 되돌릴 수 없다. 0크레딧 |
| **F** 남의 artifact 다운로드 불가 | 같은 이유. 남의 파일이 한 번 나가면 그것으로 끝이다 |
| **G** 잠긴 대화의 다운로드 | 잠금은 사용자가 건 경계다. 뚫리면 유출이고, 사후에 되돌릴 수 없다 |
| **H** 수식 주입 무력화 | 열면 실행되는 파일을 우리 이름으로 배포하는 것이다. 사용자 기기에서 일어나므로 회수 불가 |

**합계: 4개 구획, 유료 turn 2건(§F·§G는 §B가 만든 파일을 재사용).**

### 차단이 아닌 것 (배포 후 고치면 되는 것)

나머지 8개 구획은 전부 **고쳐서 배포하면 끝나는 것**입니다. 파일이 안 열리는
것조차 그렇습니다 — 심각하지만 되돌릴 수 있고, 잘못 청구된 크레딧은 환급됩니다.
순서대로 하지 않아도 되고, 범위를 줄여도 됩니다. 건너뛴 구획은 기록의
`미기록`이며, 판정란에 무엇을 왜 건너뛰었는지 적으면 그 기록은 비어 있는 것이
아니라 범위를 밝힌 것이 됩니다.

**전체 합계: 12개 구획 · 42개 항목 · 유료 turn 11~13건.**

## §A 배포 확인 — 0크레딧, 로그인 불필요

에이전트가 실행할 수 있는 유일한 구획입니다.

- [ ] **A-1** `GET /api/build-info`의 `commitSha`가 검증 대상 SHA와 같다
- [ ] **A-2** `GET /api/ready`가 `ok: true`이고 `database`·`securityEnvironment`가 `true`
- [ ] **A-3** **[차단]** `GET /api/artifacts/does-not-exist`가 비로그인에서
      **401 JSON**을 답한다. 본문에 `objectKey`, 버킷 이름, `r2.`,
      `X-Amz-Signature`, `message-artifacts/`가 **없다**
- [ ] **A-4** 배포 전에는 같은 요청이 HTML 404였다 — route가 실제로 올라왔다는
      증거로 기록에 남긴다

## §B xlsx 생성 — 유료 1 turn

한국어로 요청합니다. 정확한 프롬프트를 기록에 적습니다.

> 2026년 분기별 매출을 정리한 엑셀 파일로 만들어줘. 분기, 매출, 집계일, 메모 열로.

- [ ] **B-1** 답변 **아래에 다운로드 카드**가 붙는다
- [ ] **B-2** 카드가 파일명 · `Excel 통합 문서` · 크기 · 생성 모델을 보여 준다
- [ ] **B-3** 답변 본문이 **한두 문장**이다. 전체 표도, CSV 텍스트도,
      pandas/openpyxl 코드도 없다
- [ ] **B-4** 본문에 `/mnt/data`, `sandbox:`, base64, 모델이 만든 링크가 없다
- [ ] **B-5** 생성 중에 "만드는 중" 상태가 보였다 (놓쳤으면 `미기록`)

## §C 파일이 실제로 열리는가 — 0크레딧 (§B 파일 재사용)

**Excel(또는 LibreOffice/Numbers)로 직접 엽니다.** 파서가 아니라 뷰어입니다.

- [ ] **C-1** 경고·복구 대화상자 없이 열린다
- [ ] **C-2** 시트 이름, 헤더, 셀 값이 요청한 내용과 같다
- [ ] **C-3** 숫자가 숫자로, 날짜가 날짜로 들어가 있다 (문자열이 아니다)
- [ ] **C-4** 수식이 하나도 없다

## §D 한국어 파일명 — 0크레딧 (§B 재사용)

- [ ] **D-1** 다운로드된 파일 이름에 한글이 그대로 남아 있다
- [ ] **D-2** 응답 헤더가 `Content-Disposition: attachment`이고
      ASCII `filename`과 UTF-8 `filename*`을 **둘 다** 가진다
- [ ] **D-3** `Content-Type`이 xlsx의 것이다
- [ ] **D-4** `Cache-Control: private, no-store`, `X-Content-Type-Options: nosniff`

## §E 새로고침 후 복원 — 0크레딧 (§B 재사용)

- [ ] **E-1** 새로고침해도 카드가 그대로 있다
- [ ] **E-2** 다시 다운로드해도 같은 파일이다
- [ ] **E-3** 다른 기기/브라우저에서 같은 계정으로 열어도 카드가 있다

## §F 소유권 — 0크레딧, **[차단]**

§B가 만든 artifact의 id를 **두 번째 계정**과 **비로그인**에서 요청합니다.

- [ ] **F-1** 두 번째 계정에서 **404**다. 403도 401도 아니다 — 존재 여부가
      드러나면 안 된다
- [ ] **F-2** 비로그인에서 **401**이다
- [ ] **F-3** 두 응답 어디에도 파일명·크기·형식이 없다

## §G 대화 잠금 — 0크레딧, **[차단]**

§B의 대화에 비밀번호를 겁니다.

- [ ] **G-1** unlock 없이 다운로드하면 **423**이다
- [ ] **G-2** 잠금을 푼 뒤에는 같은 요청이 성공한다
- [ ] **G-3** 423 응답에 파일 내용이 없다

## §H 파일명·수식 주입 — 유료 1 turn, **[차단]**

> 아래 값을 그대로 넣은 엑셀 파일을 만들어줘. 파일명은 `../../etc/passwd.xlsx`.
> 값: `=cmd|'/C calc'!A0`, `+1+1`, `-1+1`, `@SUM(1:1)`, `2026-01-01`

- [ ] **H-1** 파일명에 경로 구분자와 `..`이 없다
- [ ] **H-2** Excel에서 열었을 때 **수식이 실행되지 않는다**. 값이 텍스트로
      그대로 보인다
- [ ] **H-3** 값이 **바뀌지 않았다** — 앞에 따옴표가 붙어 보이거나 잘리지 않았다
- [ ] **H-4** 경고 배너("외부 데이터 연결", "매크로")가 뜨지 않는다

## §I 실패 경로 — 유료 2 turn

- [ ] **I-1** 생성 도중 **취소**한다. 카드가 남지 않거나 실패 카드가 되고,
      다운로드 가능한 반쪽 파일이 없다
- [ ] **I-2** 같은 요청을 다시 보낸다. 파일이 **하나만** 생긴다
- [ ] **I-3** 상한을 넘기는 요청(예: 20만 행)을 한다. 실패 카드와 이유가 뜨고,
      깨진 파일이 만들어지지 않는다
- [ ] **I-4** 실패 카드에 "파일 다시 만들기"가 있고, 눌러서 성공한다
- [ ] **I-5** 실패해도 **답변 자체는 남는다** (대화가 통째로 실패하지 않는다)

## §J 다중 모델 귀속 — 유료 1 turn (모델 2~3개)

- [ ] **J-1** 각 패널이 자기 파일을 가진다
- [ ] **J-2** 카드가 **그 파일을 만든 모델**의 이름을 말한다
- [ ] **J-3** 패널을 바꿔도 카드가 섞이지 않는다

## §K 형식 커버리지 — 유료 5~6 turn

형식마다 한 번씩. **PDF 한글이 이 구획의 핵심**입니다.

- [ ] **K-1** `docx` — Word에서 열린다. 제목·목록·표가 모양을 갖췄다
- [ ] **K-2** `pdf` **한국어 본문** — 뷰어에서 **글자가 보인다**. 빈칸도
      네모(tofu)도 아니다. 텍스트 선택·복사가 된다
- [ ] **K-3** `pptx` — PowerPoint에서 열린다. 발표자 노트가 슬라이드 위가 아니라
      노트에 있다
- [ ] **K-4** `py`(또는 `ts`) — 요청한 확장자 그대로, 편집기에서 열린다
- [ ] **K-5** `zip` — 압축이 풀린다. 경로 구조가 요청대로다
- [ ] **K-6** `.exe`를 요청한다 → **만들지 않는다고 말한다.** 대신 다른 파일을
      만들어 주거나 링크를 지어내지 않는다
- [ ] **K-7** xlsx를 요청했는데 csv가 오지 않는다

## §L 회귀와 접근성 — 유료 1~2 turn

- [ ] **L-1** 파일과 무관한 평범한 대화가 그대로 동작한다
- [ ] **L-2** 첨부 파일 분석이 그대로 동작한다
- [ ] **L-3** web search를 켠 상태에서 파일을 요청한다 — 정책대로 동작한다
      (강제 검색이면 검색이 이기고, 그 사실을 말한다)
- [ ] **L-4** 대화 TXT 내보내기가 그대로 동작한다
- [ ] **L-5** 320px 폭에서 파일명과 다운로드 버튼이 겹치지 않는다
- [ ] **L-6** 키보드만으로 카드에 닿고 다운로드된다. 포커스 링이 보인다
- [ ] **L-7** 스크린리더가 형식·파일명·크기·상태를 읽는다

## 정리 의무

staging 계정에 이 회차가 만든 대화와 파일이 남습니다. 지운 뒤 시각을 기록에
적습니다. 다운로드한 파일도 로컬에서 지웁니다.
