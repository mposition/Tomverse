## 부수 관측

§B-2 재시도 중 로그에 나타난 것을 적어 둡니다. 결함은 아니지만 #632가 이용한
바로 그 경로이므로 기록에 남깁니다.

```
06:12:13.899-.952  GET  /api/conversations/cmt2jlt7f…  ×4   ← 대화 2로 전환
06:12:17.130       PATCH /api/conversations/cmt2jlt7f…  200 (131ms)
```

대화 2로 전환한 지 약 3초 뒤 **대화 2 자신에 대한 PATCH**가 일어납니다. 화면에
올라온 대화의 모델 설정을 서버에 확인시키는 정상 동작이며, 직후 `GET`에서 대화 2의
값이 스냅샷과 같았으므로 쓴 값도 원래 값과 동일합니다. #632는 이 쓰기가 *직전
대화의* 상태를 담은 채 일어나는 것이었습니다.

### 발견 1 — 어시스턴트로 시작한 대화의 첫 turn이 거절된다

§14.0의 채택은 서버에서 정상 동작하지만, 클라이언트가 그 결과를 읽지 않고
자기 목록으로 다음 요청을 보냈습니다. 같은 불일치가 두 경로에서 각각 다른
오류로 나타납니다.

| composer 모델 수 | 경로 | 오류 |
|---|---|---|
| 1 | `POST /api/chat` | `403 MODEL_NOT_SELECTED` (Trace `627e9859-…`) |
| 2 이상 | `POST /api/chat/preflight` | `One or more comparison models are not selected…` (Trace `9219480c-…`) |

첫 번째는 이 회차 직전에 PR #700이 고쳤고, 두 번째는 이 회차의 B-5가 발견해
PR #705가 고쳤습니다. **어시스턴트 기능의 가장 흔한 첫 사용 경로**(새 대화에서
어시스턴트를 고르고 말을 거는 것)가 막히는 결함이므로, production flag 활성화
전에 반드시 닫혀야 합니다.

### 발견 2 — §B-5 항목의 문구가 이 결함을 잡지 못한다

항목은 "새 대화를 profile과 함께 만들면 profile의 `modelIds`가 초기 선택이
된다"이며, **서버 값만 보면 통과**합니다. 실제로 채택은 일어났고, 실패한 것은
그 채택을 모르는 화면이었습니다. 화면과 서버가 어긋나 첫 turn이 죽는 상태를
이 문구는 기술하지 못합니다.

다음 template revision에서 "그 대화의 **첫 turn이 성공하고**, 화면의 모델
표시도 profile의 모델을 가리킨다"를 항목에 넣을 것을 제안합니다. 이 회차는
template `2026-08-20a`로 실행됐으므로 문구를 바꾸지 않았습니다.

### 발견 3 — §B-2는 서버 로그로 판정할 수 없다

Railway http 로그의 `totalDuration`은 edge–upstream 구간 값이라 클라이언트
throttling을 반영하지 않고, 요청·응답 양 구간이 지연되므로 서버 timestamp로
클라이언트의 전환 시점을 역산할 수 없습니다. 이 항목은 **클라이언트 측 증거**
(DevTools `Time` 열 또는 PATCH `Pending` 상태의 화면)로만 판정됩니다. 다음
회차에서도 같은 방식이 필요합니다.
