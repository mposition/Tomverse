The gate is `evidence-ready`, not `approved`. That is not a formality being
observed for its own sake: the registry's own rule is that `approvedBy` must
carry a gate-owner approval and an independent-reviewer approval **from
different people**, so one subject cannot complete it however senior they are.
`approvedAt` stays null until the second approval exists, because it timestamps
the completed approval rather than the first one.

## 3. What this evidence does not establish

A reviewer should not read the above as more than it is.

- **It covers the two packages that exist.** `chat-ui` and `api-client` are
  named in the delivery plan and are not in the tree; the criterion is
  measured over `packages/*` as it stood, so it will need re-reading when they
  arrive.
- **The Vite half is not an application build.** There is no `apps/mobile`. The
  matrix proves the packages build and run where Next.js is not the builder; it
  does not prove any mobile client works.
- **One run at one commit.** The property is standing, not historical: every PR
  re-measures it. This packet fixes a point that can be audited, not a
  guarantee about later commits.
- **`b786a97` was not itself gated.** The fast gate does not run on pushes to
  `develop`, so the merge commit carries the evidence of the run above rather
  than one of its own.

## 4. What approval requires

`governance.approvalPolicy` in the registry:

- `approvedBy` needs **two entries from different people** — one `gate-owner`,
  one `independent-reviewer`.
- `independentReviewerRule`: the independent reviewer must be a person who did
  not produce the referenced evidence. **The author of this packet produced the
  artefacts and the CI runs cited, and therefore cannot serve as the
  independent reviewer.**
- `approvedAt` must be a non-null RFC 3339 timestamp.
- `evidenceRefs` must contain immutable links or artifact identifiers.

## 5. What is recorded, and what completes it

Recorded in the registry now: `status: evidence-ready`, the gate-owner
approval, and the `evidenceRefs` above. Those references are facts about a
commit and a CI run, so they do not wait on anyone.

To complete the gate, append the second approval and set the two fields the
`approved` state requires:

```yaml
  - id: PACKAGE-01
    status: approved
    approvedBy:
      - subject: "@mposition"
        role: gate-owner
        approvedAt: "2026-08-12T23:21:58Z"
      - subject: "<a person who did not produce this evidence>"
        role: independent-reviewer
        approvedAt: "<RFC 3339>"
    approvedAt: "<RFC 3339 timestamp of the second approval>"
```

Then run `npm run verify:tomverse-chat-release-gates` and regenerate the
readable view with `npm run generate:tomverse-chat-release-gate-view` — the
committed Markdown is compared byte for byte in CI, so a hand-edit fails the
build.

One thing worth re-reading before that signature: §3. The reviewer is
approving that these two packages were framework-neutral at one commit, not
that the mechanism covers packages which do not exist yet.
