actually stops a run. No publishing adapter until S2d2, so a run opens its row,
records why there is nothing it can do, and closes.

## The three most recent changes, which are the newest code and least reviewed

1. **`declaredAbove`** in the caller lint. The previous version walked up the
   ancestors and at each level asked what any *direct child* declared, so a
   sibling `catch (prisma)` counted as the declaration of `prisma` and hid the
   module client from a use inside the `try`. It now asks only what each ancestor
   itself binds, plus, for block scopes, what its own statements declare —
   excluding a declaration whose *initialiser* contains the use, so
   `const prisma = prisma.x` still reads the outer one. **Check both directions:**
   can it still report a name as declared when it is not (hiding a client), and
   does it now report ordinary locals as free (which would make the lint
   unusable)? `for` bindings, destructuring, class fields, switch cases,
   parameters with defaults.
2. **The cycle handling** in `clientReach`. A traversal that meets a cycle now
   answers a sentinel, the sentinel propagates and is never cached, and it is
   treated as reaching a client. Check whether the sentinel can escape as a
   truthy reason string in a place that expects `null`, whether not caching
   introduces exponential re-walking on this repository's real import graph, and
   whether a legitimate module now gets refused.
3. **The route reads the database clock** to judge the deadline window, because it
   used the process clock while the trigger judges lateness with the database's.
   Check the failure path (503 `database_clock_unavailable`), whether the extra
   query belongs before the duplicate-run check, and whether any test now asserts
   the skew case with a fake that could not happen.

## The rest

1. **The migration.** Every path: insert with and without a deadline; update while
   running (heartbeat, close on time, close late, close failed); update after
   closing; attempts to add, move or null a deadline. Can a late run be recorded
   `succeeded` by any route? Can it break `completeScheduledJob`,
   `failScheduledJob`, or the auto-fix fields on rows with no deadline?
2. **`runBoundedMarketingTransaction`.** Refuses below PostgreSQL 17, and refuses
   when a `transaction_timeout` is already running because 17 starts a timer only
   when none is active. Are `0` and `0ms` the only spellings of off? Does the
   ordering keep all three GUCs armed?
3. **The route.** Bearer comparison, body strictness, duplicate run ids, and the
   close paths — can two run?
4. **The service.** Does the supervisor kill in every case, including a worker that
   ignores signals or never spawns? Any retry? Can either hold anything beyond
   `MARKETING_PUBLISH_SECRET` and `MARKETING_PUBLISH_URL`?
5. **The tests.** The recurring failure here is **a test whose fake agrees with the
   code and disagrees with the real dependency** — eleven times now. Is the
   `P2039` shape the heartbeat reads what Prisma actually raises for a
   trigger-raised custom SQLSTATE on `updateMany`? Would each integration case
   have failed the version it was written against?
